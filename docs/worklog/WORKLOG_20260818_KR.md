## 2. 🐛 STAC 요약에 footprint가 빠져 있었다

`download_south_korea_month.py`가 검색 66장을 전부 훑고도 **"남한 걸침 0장"**
을 냈다. 원인은 이 도구가 아니라 그 아래였다.

```python
# s1/stac/models.py — S1ItemSummary 에 geometry 필드가 없었다
bbox: Optional[List[float]]      # ← bbox 는 있는데
# geometry 가 없다 → c.get("geometry") 가 항상 None → 판정 스킵
```

`extract_s1_summary()`가 `item.geometry`를 버리고 있어서, 요약 dict를 받아
footprint로 판정하는 쪽은 **무조건 빈 결과**를 봤다. bbox만으로 판정하면 기울어진
스와스의 빈 삼각형까지 육지로 세는 문제(SCENE_FOOTPRINT_REAUDIT) 때문에 일부러
footprint를 쓰게 해놨는데, 정작 그 데이터가 전달되지 않았다.

**조치** — `S1ItemSummary.geometry` 추가 + `extract_s1_summary`에서 채운다.
고친 뒤 같은 명령이 **남한 걸침 57장**을 정상 판정했다(ISSUES #18).

## 5. external DEM이 남한 전용이었다 — 한반도판을 새로 구웠다

### 발단

"한반도 8월 전량 전처리"로 범위가 넓어지자 DEM이 걸렸다.

```text
korea_full_cop30.tif        125.0~131.0E, 32.9~39.9N     ← 남한 + 제주 전용
북한 최북단                                    약 43.0N     ← 3.1° 밖
```

미처리 씬의 footprint를 실측하니 북위 **43.57°**, 서경 **122.03°**까지 나왔다.
DEM 밖은 RTC 산출물에서 무효로 남으므로, 그대로 돌리면 **북한이 통째로 빈
산출물**이 나온다. 오류 없이 결과만 비는 종류라 로그로는 안 보인다(ISSUES #13의
확대판 → #17로 등록).

### 조치

```bash
python -m s1.tools.dem.make_basin_dem --bounds 123.5,32.8,131.3,43.3 --name korea_peninsula
# korea_peninsula_cop30.tif  123.50~131.30E 32.80~43.30N  타일 78  1,713 MB
```

COP30 타일 가용성을 먼저 확인했다(E123~131 × N32~43). 빠진 칸은 전부 바다라
문제없고, **한반도 육지 타일은 전부 있다.**

같은 날 [PREPROCESSING_SPEC_KR.md](../pipeline/PREPROCESSING_SPEC_KR.md)가
신설되면서 **한반도 처리 DEM은 `korea_peninsula_cop30.tif` 하나로 확정**됐다.
보유 DEM 8종의 범위를 실측한 표와 나머지 전처리 파라미터(편파 VH·Frost·EGM
끄기·10 m·EPSG:4326)까지 그 문서가 정본이다.

### 기존 산출물은 재처리가 필요한가 — 재지 않고 답하지 않았다

DEM을 바꿨으니 기존 것도 다시 구워야 하나? **씬마다 다르다.** 그래서 가정하지
않고 `(footprint ∩ 한반도)` 중 옛 DEM 상자 **밖** 비율을 씬별로 계산했다.

| 판정 | 씬 | 조치 |
| --- | ---: | --- |
| 손실 < 1% | 15 | 그대로 둔다. 이 중 11장이 이미 VH 완료 |
| 손실 ≥ 1% | 17 | peninsula DEM 으로 처리 — **전부 미처리분이었다** |

**이미 처리한 11장은 하나도 재처리 대상이 아니었다**(대부분 0.0%). 남한 궤도의
프레임이라 옛 DEM 안에 온전히 들어간다. 재처리 11장(약 5시간)을 아꼈고, 무엇보다
"DEM을 바꿨으니 다 다시"라는 반사적 판단을 숫자로 걸렀다.

반대로 손실 100%짜리가 7장 있었다 — `226A`·`31FB`·`E6FC`·`65AB`·`9A5C`·`B808`·
`A54D`·`7AE5`. 전부 북한·동해 프레임이다.

### ⚠ 강제 종료가 빈 산출물을 남겼다 — 확인을 잘못했다

배치를 죽인 뒤 "부분 산출물 없음"으로 판단했는데 **틀렸다.** 그때 실제로 처리
중이던 씬은 `D635`(배치 B)였는데, 엉뚱하게 `0D06`·`5ACA`(새 배치가 곧 처리할
씬)를 찾아보고 깨끗하다고 결론냈다. `D635`는 **0.15 GB짜리 값이 전부 0인
껍데기**로 남았다.

이게 고약한 이유는 세 가지다.

1. **열린다.** `rasterio`로 크기·bounds·CRS가 정상으로 보이고, 성기게 읽으면
   유효화소 100%로 나온다. README가 경고한 "쓰다 만 파일도 열린다"가 이것이다.
2. **배치가 건너뛴다.** 파일이 있으면 처리 완료로 보므로 재실행해도 안 고쳐진다.
3. **하필 제일 중요한 씬이었다.** `D635`는 08-13 rel 134 패스에서 **남한 커버가
   가장 넓은(85.6%)** 프레임이다.

**판정법** — 크기만으로는 애매하다(정상 산출물도 1.6~2.9 GB로 폭이 넓다).
**압축률**이 갈랐다.

| 씬 | 용량 | 무압축 대비 | 비영값 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 정상 19장 | 1.72~2.85 GB | 51.8~87.4% | 100% | OK |
| **`D635`** | **0.15 GB** | **5.1%** | **0.0%** | ❌ 빈 파일 |

값이 전부 0이면 deflate가 극단적으로 잘 먹어 **압축률이 한 자릿수**로 떨어진다.
20장 전수 점검 결과 문제는 `D635` 하나뿐이었고, 삭제 후 재처리 대기열에 넣었다.

> **규칙**: 배치를 강제 종료했으면 **그 시점 temp 폴더에 있던 씬**의 산출물을
> 지운다. 그리고 "부분 산출물 없음"을 눈으로 확인하지 말고 **압축률·비영값으로
> 전수 점검**한다.

### 진행 중이던 배치는 중단했다

남한 11장 배치를 돌리는 중이었는데, 남은 6장 중 **3장(`0868` 2.4% · `D2A0` 2.7%
· `7C24` 17.9%)이 손실 대상**이었다. 그대로 끝내면 어차피 재처리라 중단하고
peninsula DEM 으로 다시 걸었다. 부분 산출물이 남지 않은 것과 완료본 11장이
온전한 것은 확인했다(강제 종료 후 점검 — README 주의사항).

### 🐛 "tif가 있으면 완료"가 틀렸다

SNAP `gpt`는 출력 tif를 **처리하는 내내 쓴다.** 만들면서 확인해 보니 처리 중이던
`0868`이 이미 2.32 GB짜리 tif를 갖고 있었고, 방금 시작한 `8E47`은 0 바이트였다.
파일 존재로 완료를 세면 **굽는 중인 씬이 완료로 잡힌다.** 그래서 판정을
**배치 러너의 임시폴더(`%TEMP%/frostrtc_*`) 우선**으로 뒤집었다 — 그 폴더가 있는
동안이 곧 처리 중이다.

경과시간도 한 번 틀렸다. 임시폴더 안 zip의 mtime을 쟀더니 "20시간 전 시작"이
나왔는데, `shutil.copy2`가 원본 시각을 그대로 물려주기 때문이다. **폴더
생성시각**으로 바꿔 실제 배치 시작(08:57·10:11)과 맞췄다.

### 위치는 어떻게 "충남"이 되나

시도 경계를 **500 m로 단순화한 GeoJSON 한 장**(28개 구역, 326 KB)으로 구워 두고
([build_sido_geojson.py](../../s1/tools/monitor/build_sido_geojson.py)), footprint
표본 격자점이 어느 시도에 떨어지는지 세어 육지 표본 8% 이상만 적는다.
남한 17개는 읍면동 경계를 시도로 병합, 북한 11개는 WFP COD-AB adm1이다.
겹침%와 위치를 **같은 격자 한 번**으로 구해 프레임당 비용을 두 배로 만들지 않았다.

검증: 하강궤도 rel134 한 패스가 `제주 → 전남·경남·전북 → 경북·충남·충북 →
강원·경기·강원도(북) → 함경남도·양강도·함경북도`로 남→북 순서로 찍혔다.

### 처리 시간 — 씬당 30분이 아니라 80분대였다

peninsula DEM(1.71 GB, 기존의 2.3배)으로 바꾸고 북부 대형 프레임을 돌리자
씬당 **72~107분**(평균 약 85분)이 걸렸다. 남한 씬 기준 30분으로 잡았던 예상이
3배 가까이 빗나갔다. gpt 메모리도 4~6 GB에서 **9~11 GB**로 올랐다.

**배치 2개 병렬이 RAM 상한**이다(32 GB 중 여유 0.4 GB). 세 번째 배치를 띄우면
스와핑이 나므로, 추가 작업은 앞 배치가 끝난 뒤로 큐를 건다.
