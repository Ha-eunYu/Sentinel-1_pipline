## 2. 8/7 결론이 뒤집혔다 — 섬진강·평림은 가능하다

가능"으로 끝났다. **그 결론은 조회 시점에만 맞았다.**

2026-08-07 ASC127(S1D 3장)이 섬진강·평림을 100% 덮는데, 8/7 최초 조회 때는
카탈로그에 없었다. **촬영에서 등재까지 수 시간**이 걸리기 때문이다.

> 교훈: "아카이브에 없다"는 결론에는 **조회 시각**을 함께 적어야 한다.
> 당일 관측은 몇 시간 뒤 다시 봐야 한다.

8월 IW GRD **78장 전량**을 (촬영일 × 상대궤도)로 묶어 재점검한 결과는
[REPORT_AUG_SAR_KR.md](../../../2026_drought_map/REPORT_AUG_SAR_KR.md) §1-2에
표로 옮겼다. 핵심은 셋이다.

1. **8개 유역을 한 궤도로 덮는 날은 두 해 모두 없다.** 유역별 궤도 배정이

2. 6개 댐 유역·낙동강·한강은 **ASC54**, 섬진강·영산강·평림·금강은 **ASC127**.

## 5. 자동 캐시 DEM의 하구 결함 — 정량 확인

`rtc_basin_extdem.py` 주석이 경고하던 문제(영산강 제약의 20.2%)를 낙동강에서
직접 쟀다. **같은 granule을 두 DEM으로 처리해 견줬다.**

| granule | 자동 캐시 DEM | external DEM | 차이 |
| --- | ---: | ---: | ---: |
| D0A4 (2025-08-06) | 777.711 km² | 765.226 km² | **−12.485** |
| 3B05 (2026-08-02) | 326.653 km² | 314.169 km² | **−12.484** |

(낙동강 제약 안 결측 면적. 절대값이 큰 것은 프레임 밖 영역이 포함돼서다 —
**차이만 보면 된다.**)

두 해 모두 정확히 **12.48 km²**가 되살아났다. 위치는 128.935~129.011E,
35.107~35.259N — 낙동강 본류 하류로, 두 해가 **경위도 소수 4자리까지 동일한
정적 결함**이었다.

### 5-1. 모자이크로도 안 메워진다

같은 패스의 프레임은 모두 같은 DEM을 쓰므로 이웃 프레임이 덮어주지 못한다.
자동 DEM 판 모자이크의 낙동강 제약 결측은 19.42 / 19.33 km²(1.93%)였고,
그중 62.6%가 이 단일 덩어리였다.

### 5-2. 창 패치 → 전 granule 재처리로 대체

처음에는 `rtc_basin_extdem.py --window`로 하구만 잘라 덧댔다(씬당 233초).
이후 ASC54 5장을 전부 external DEM으로 재처리하자 **패치가 불필요해졌다** —
패치를 빼고 모자이크를 다시 만들어도 결측이 6.864 / 6.869 km²로 **완전히
동일**했다. 패치 2장은 `downloads/rtc_extdem/_superseded/`로 격리했다.

### 5-3. dB가 움직인다 — 임계값에 영향

DEM을 바꾸면 Terrain-Flattening 결과가 달라져 dB 절대값이 이동한다.

| | 2025-08-06 | 2026-08-02 | 연도 간 차이 변화 |
| --- | ---: | ---: | ---: |
| P50 이동 (자동→external) | +0.38 dB | +0.46 dB | **0.08 dB** |
| gee 임계값 (aug → v9) | −20.32 → −19.62 | −20.32 → −19.79 | 0.17 dB |

**두 해가 같은 방향·비슷한 폭으로 움직여 연도 간 비교는 거의 영향받지 않는다.**
다만 변화율은 최대 4.5%p 바뀌었다(성덕 −29.7% → −25.2%). **DEM을 섞으면 안
된다**는 뜻이다 — 한 비교쌍 안에서는 반드시 같은 DEM 방식을 써야 한다.

### 5-4. 남은 결측은 미관측이다

낙동강 제약 결측 6.86 km²(0.68%) 중 최대 덩어리 4.23 km²는
127.51~127.69E, 35.32~35.52N에 있는데 **ASC54 스와스 밖**이라 어떤 granule도
덮지 못한다. 창을 잡아 패치를 시도했을 때 `--min-overlap 99`에서 **작업 0건**이
나온 것이 단서였다.

| 낙동강 제약 | 2025-08-06 | 2026-08-02 |
| --- | ---: | ---: |
| 스와스 안 | 1001.14 km² (99.4%) | 1001.12 km² (99.4%) |
| 스와스 밖(미관측) | 6.42 km² (0.6%) | 6.44 km² (0.6%) |
| 스와스 안인데 무효(DEM) | 0.59 km² (0.06%) | 0.51 km² (0.05%) |

> **결측은 두 갈래로 나눠 봐야 한다.** footprint 안인데 무효면 DEM 결함이라
> 고칠 수 있고, footprint 밖이면 안 찍힌 것이라 못 고친다. 나누지 않으면
> 고칠 수 없는 것을 고치려 시간을 쓴다.

## 6. `korea_full_cop30.tif` — 전국 단일 DEM

유역별 DEM을 골라 쓰다 보니 범위가 모자라는 일이 반복됐다.

| DEM | 범위 | 한강 | 금강 |
| --- | --- | ---: | ---: |
| `korea_cop30` | 38.7°N까지 | 93.3% (부족) | 100% |
| `han_cop30` | 39.24°N까지 | 100% | 99.68% (부족) |
| **`korea_full_cop30`** | **125.0~131.0E, 32.9~39.9N** | **100%** | **100%** |

```bash
python -m s1.tools.dem.make_basin_dem --bounds 125.0,32.9,131.0,39.9 --name korea_full
```

37타일 733 MB. **대권역 21개 + 댐유역 8개 전부 nodata 0개**를 확인했다
(제주도 포함). 앞으로는 이것 하나만 쓰면 된다.

⚠ 세 가지는 그대로다.
- **VRT는 external DEM으로 못 읽는다** — GeoTIFF로 구울 것.
- **`--dem-egm`을 켜지 말 것** — COP30은 타원체고라 이중 보정되면 약 25 m 어긋난다.
- **DEM은 분석 영역만 덮으면 된다** — granule 가장자리가 DEM 밖이라 무효로
  남는 것은 정상이다.

### 7-1. 환경이 갈려 있다

`s1_pipeline`에 STAC(`pystac_client`)이, `sar-gee`에 shp 리더(`pyogrio`)가 있고
**둘 다 갖춘 환경이 없다.** 그래서 유역 폴리곤을 GeoJSON으로 한 번 떨궈
양쪽이 같은 것을 보게 했다(`geojson/aoi_seomjin_yeongsan.geojson` 등).

### 7-2. `candidates`에는 footprint가 없다

`list_s1_items_for_date`가 돌려주는 후보는 `extract_s1_summary`를 거치며
**bbox만 남고 geometry가 빠진다.** footprint로 판정하려면 `client.search()`로
원본 item을 직접 받아야 한다. 이걸 모르고 `c.get("geometry")`를 쓰면 조용히
**전부 걸러진다**(실제로 "섬진강 8월 씬 0장"이라는 오답이 나왔다).

## 8. 진행 감시 요령

`conda run ... *> 로그`로 리다이렉트하면 **파이썬 표준출력이 블록 버퍼링**돼
진행이 실시간으로 안 보인다(프로세스 종료 시 한꺼번에 flush). gpt의 stderr만
흘러나온다. 진행 확인은 **산출 폴더의 tif 크기**로 보는 편이 확실하다.

단 SNAP은 그래프 시작 시 출력 tif를 **0바이트로 먼저 만들고** 기록은 마지막에
한다. 파일 등장은 "완료"가 아니라 "씬 시작" 신호다.

**DEM 판별법**: 자동 캐시 DEM을 쓰면 로그에 `Copernicus_DSM_COG_..._DEM.tif`
줄이 찍힌다. external DEM이면 **0줄**이다. 실제로 이 차이로 8/7 배치가 자동
DEM이었음을 확정했다(`_vh_aug25.log` 7줄 / `_vh_a127_25.log` 0줄).
