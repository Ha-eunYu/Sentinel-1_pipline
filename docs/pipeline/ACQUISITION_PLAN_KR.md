# 촬영 계획으로 "앞으로 찍을 것" 보기 (acquisition_plan)

카탈로그 감시([SCENE_MONITOR_KR.md](SCENE_MONITOR_KR.md))는 **이미 찍힌 것**만
본다. 등재까지 3~6시간 걸리니 "오늘 저녁에 우리 유역이 찍히나?"에는 답하지
못한다. 그 답은 ESA가 **3주치 미리 공개하는 계획 KML**에 있다.

| 구성 | 경로 | 역할 |
| --- | --- | --- |
| 본체 | [acquisition_plan.py](../../s1/tools/monitor/acquisition_plan.py) | 계획 KML 수집·파싱 → 한반도 통과 목록 |
| 공용 부품 | [footprint_label.py](../../s1/tools/monitor/footprint_label.py) | 시도 판정·지점 포함 판정(현황 창과 공유) |
| 관심 지점 | `data/dam_points_kwater.csv` | 다목적댐 21 · 다목적보 16 · 용수댐 14 = **51지점** |
| KML 캐시 | `downloads/plans/*.kml` | 위성별 최신 계획(3 MB 안팎). 최근 6개만 남긴다 |
| 결과 캐시 | `downloads/plan_cache.json` | 현황 창이 즉시 그리는 데 쓴다 |

- **의존성 없음.** `urllib`·`xml.etree`·`csv` 등 표준 라이브러리만. 인증 불필요.
- 현황 창([SCENE_DASHBOARD_KR.md](SCENE_DASHBOARD_KR.md))의 **'촬영 예정' 표**가
  이 도구를 그대로 쓴다(기본 6시간마다 갱신).

---

## 1. 동작

```text
1) 계획 페이지 긁기   sentinels.copernicus.eu/.../acquisition-plans
                     → s1c_mp_user_<시작>_<끝>, s1d_mp_user_... 링크 수집
2) 최신 판만 내려받기  위성별로 시작이 가장 늦은 것 (겹쳐 가며 여러 판이 올라온다)
3) KML 파싱          Placemark 하나 = datatake 하나
                     TimeSpan(begin/end, UTC) + ExtendedData(위성·모드·궤도)
                     + LinearRing(발자국)
4) 한반도 필터        bbox 1차 → 육지 표본 격자로 커버% 산정
5) 라벨 붙이기        시도 이름(상위 3개) + 포함되는 댐·보 이름
```

S1A는 건너뛴다(2026-06-29 퇴역). 기본은 `--mode IW`다 — 한반도 육상 관측은
전부 IW이고, WV(대양)·EW까지 세면 목록이 지저분해진다.

### 한반도 육지 격자를 미리 만든다

계획의 datatake는 **위도 10°를 넘는 긴 띠**다. 촬영된 프레임처럼 건건이 격자를
뿌리면 한 건에 수만 점이 들어 **35건에 50초**가 걸렸다. 그래서 한반도 육지 점을
**한 번만** 만들어 두고(`KoreaGrid`), datatake마다 "그중 몇 개가 이 띠 안에
드나"만 센다 — 같은 일이 **0.9초**로 끝난다.

덤으로 숫자의 뜻이 분명해진다. `한반도 %`는 띠 안에서 육지가 차지하는 비율이
아니라 **한반도 육지의 몇 %를 덮나**다. rel134가 69.5%로 가장 크게 나오는 것이
관측 달력([ORBIT_CALENDAR_202607_08_KR.md](ORBIT_CALENDAR_202607_08_KR.md))과
맞는다 — 남북을 한 번에 훑는 하강 패스다.

격자 간격 기본값은 **0.1°(≈10 km)**다. 촬영된 프레임 판정(0.05°)보다 성긴 이유는
용도가 "어느 도를 지나나"이기 때문이고, 격자 생성이 전체 시간의 대부분이라
그렇다(0.05°=20초, 0.08°=6.3초, 0.1°=3.1초). **댐·보 판정은 격자와 무관하게
지점 좌표로 정확히** 한다.

## 2. 실행

```bash
python -m s1.tools.monitor.acquisition_plan               # 앞으로 7일
python -m s1.tools.monitor.acquisition_plan --days 14     # 더 멀리
python -m s1.tools.monitor.acquisition_plan --dams-only   # 댐·보가 드는 것만
python -m s1.tools.monitor.acquisition_plan --json        # 기계용
```

```text
■ 앞으로 10일 한반도 촬영 계획 — 6건 (ESA 계획 KML, 갱신 08-18 13:07 KST)
  08-19 18:30 KST  S1D rel127  전남·전북·경남       한반도  15.5%  댐·보 16곳: 주암댐, 남강댐, …
  08-21 06:14 KST  S1C rel 61  경북·함경북도·경남     한반도  19.9%  댐·보 29곳: 안동댐, 임하댐, …
  08-26 06:24 KST  S1C rel134  함경남도·함경북도·강원  한반도  69.5%  댐·보 42곳: 소양강댐, 대청댐, …
```

**시각은 KST**다. 계획 KML은 UTC로 적혀 있고 하강궤도는 UTC 21시대라, 그대로
읽으면 날짜가 하루 어긋난다([SCENE_MONITOR_KR.md](SCENE_MONITOR_KR.md) 5-4).

| 옵션 | 기본 | 의미 |
| --- | --- | --- |
| `--days` | 7 | 앞으로 며칠 |
| `--mode` | `IW` | 빈 문자열이면 모드 전부 |
| `--step` | 0.1 | 육지 표본 격자 간격(도) |
| `--dams-only` | 꺼짐 | 댐·보가 하나라도 드는 통과만 |
| `--json` | 꺼짐 | JSON 출력 |

## 3. 관심 지점 51곳

`data/dam_points_kwater.csv` — `구분,지점명,위도,경도`.

| 구분 | 개수 | 비고 |
| --- | ---: | --- |
| 다목적댐 | 21 | 소양강·충주·대청·안동·임하·합천·남강·주암… |
| 다목적보 | 16 | 4대강 보(강정고령·달성·세종·공주·백제·승촌·죽산…) |
| 용수댐 | 14 | 영천·운문·사연·대암·평림… |

출처는 `SentinelObservationPlan/`에 딸려 있던 CSV 3개를 합친 것이다(K-water
관리 시설 개수와 일치). **검증**(2026-08-18): 51지점을 시도 경계에 찍어 보니
육지 밖·중복이 하나도 없고 배정도 맞았다(소양강댐→강원, 세종보→세종,
평림댐→전남, 연초·구천댐→경남 거제).

저장소의 다른 댐 자료와 역할이 다르다 — `reservoir_points.json`은 **호수 중심**,
`geojson/dams8.geojson`은 **유역 폴리곤**, 이 CSV는 **댐·보 구조물 지점**이다.
지점을 바꾸려면 CSV만 고치면 된다(코드 수정 불필요).

## 4. ⚠ 한계

1. **계획은 계획이다.** ESA는 수시로 갱신하고 실제 촬영이 빠지기도 한다 —
   2026-07-08 S1C 공백이 그랬다(README "촬영 계획 확인법"). 이 출력은 예정이지
   보장이 아니다.
2. **계획 기간을 넘어가면 빈다.** 계획 파일은 약 3주치다. `--days 30`을 줘도
   파일이 덮는 데까지만 나온다.
3. **datatake 단위다.** 실제 제품(프레임)은 이 띠를 잘라 만든다. 그래서 계획
   한 줄이 카탈로그에서는 씬 여러 장이 된다(rel134 한 패스 = 7프레임).
4. **페이지 구조에 기댄다.** 링크를 HTML에서 정규식으로 긁으므로 ESA가 페이지를
   바꾸면 조용히 0건이 된다. 0건이 계속되면 `plan_links()`부터 확인할 것.
5. **모드 필터 기본 IW.** SM/EW 관측을 봐야 하면 `--mode ""`.

## 5. 이 도구를 새로 만든 이유

같은 일을 하는 `SentinelObservationPlan.exe`(262 MB, PyInstaller, 2026-07-07)가
저장소에 들어와 있었지만 **소스가 없었다.** 감사도 수정도 안 되고, ESA가 KML
형식이나 페이지를 바꾸면 손댈 방법이 없다. 게다가 262 MB 바이너리가 git 추적
대상으로 놓여 있어 `git add -A` 한 번이면 커밋될 뻔했다(GitHub 파일당 100 MB
한도).

이 저장소에는 이미 필요한 부품이 있었다 — 순수 파이썬 point-in-polygon
(`monitor_new_scenes`), 시도 경계(`sido_simplified.geojson`), 한반도 경계.
그래서 **표준 라이브러리 300줄**로 다시 썼다. exe는 `.gitignore`에 넣어 두되
지우지는 않았다(비교 대상으로 남긴다).
