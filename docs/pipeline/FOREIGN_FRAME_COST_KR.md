## 2. 회차별 내역

### ① 2026-07-22 — bbox 판정 (24씬)

`Korea_Peninsula.geojson`의 **bbox**로 "한반도를 찍었다"를 판정했다. SAR
프레임은 궤도 방위각만큼 기울어진 평행사변형이라, 축에 정렬된 사각형으로
감싸면 **실제로 찍지 않은 삼각형 여백**이 크게 남는다. 그 여백이 한반도에
걸치면 100% 바다인 프레임도 통과한다.

| 처리 단계 | 씬 | 낭비 |
| --- | --- | --- |
| RTC + GTC 완료 | `FAA4`·`88AF`·`9919`·`B5A5`·`D440`·`E215`·`3883` (7) | **14회 처리** (씬당 RTC 1 + GTC 1) |
| RTC만 완료 | `3167`·`E067`·`4C8A`·`D298`·`3191`·`4C7C`·`E265` (7) | 7회 처리 |
| 다운로드만 | `4685`·`A8F8`·`BCBF`·`C7AD`·`DAF9`·`4D62`·`5C3C`·`6668`·`F45C`·`754B` (10) | 다운로드 대역 |

`excluded_china_japan/`의 14개 tif = **8.96 GB**. 개별 산출물이 7 MB~1.35 GB로
편차가 큰데, 한반도에서 먼 프레임일수록 DEM 밖이 많아 작아진다.

> **처리시간은 로그가 남지 않아 산정하지 못했다.** 같은 규격 GRD의 실측이
> 씬당 15~100분이므로 21회 처리는 **대략 10~20시간대**로 보이나, 근거가 없어
> 추정으로만 적는다.

### ② 2026-07-23 — 재유입 (5씬)

①에서 zip을 지워 배치 큐에서 뺐는데, NAS(X드라이브) `rsync
--ignore-existing`이 **원본에 남아 있던 파일을 다시 끌어왔다.** 로컬에서
지운 것은 rsync에게 "없는 파일"이라 매번 복원된다.

2026-08-21 확인 결과 아직 로컬에 남아 있는 재유입분:

| 씬 | zip 날짜 | 한반도% | VH RTC |
| --- | --- | ---: | --- |
| `D298`·`3191`·`4C7C` | 07-18 | **0.00** | 없음 |
| `754B` | 07-23 | **0.00** | **있음 (08-19 처리)** |
| `FAA4` | 08-17 | 29.50 | 없음 |

**`754B`가 이 문제의 실물이다.** 7/22에 "한반도 0%"로 판정해 지웠는데
다음 날 재유입됐고, 한 달 뒤 VH 통일 재처리 배치가 **아무 의심 없이 집어
1.25 GB짜리 산출물을 만들었다.** 배치는 zip이 있으면 처리한다 — 제외 이력을
모른다.

(`FAA4`는 29.5%로 실제로는 한반도를 찍는다. ① 당시 STAC 공칭 geometry로
0%로 판정됐던 것이 실측 footprint로는 다르게 나온 경우다 — 4절 참고.)

### ③ 2026-08-21 — 공칭 geometry + 남/북 오분류 (3씬)

## 3. 왜 세 번 다 새어 나갔나

```text
검색 bbox ──▶ STAC 필터 ──▶ 분류 ──▶ 다운로드 ──▶ RTC 배치
   │            │            │                      │
   ①          ③-1          ③-2                    ②
 bbox로      공칭         "남한 아님        제외 이력을
 판정        geometry      = 북한"          모른다
```

### ③-1. STAC `item.geometry`는 **공칭** 폴리곤이다

`touches_korea()`는 STAC이 준 geometry로 판정하는데, 이 값이 원본 zip의
`preview/map-overlay.kml` 실측 footprint와 **다르다.** 대마도 프레임은
공칭으로는 한반도에 살짝 걸쳐 필터를 통과했고, KML 실측으로는 **0.00%**였다.

> bbox 대신 footprint를 쓰라는 교훈이 **검색 단계에서는 아직 관철되지 않았다.**
> footprint 판정은 zip을 받아야 가능하므로, 검색 단계에서 완전히 막을 수는
> 없다. **받은 직후 KML로 재판정해 격리**하는 관문이 필요하다.

### ③-2. "남한이 아님"을 "북한임"으로 단정했다

조사 스크립트가 이렇게 분류했다.

```python
if 남한교차 > 0.5:  남한
else:              북한전용        # ← 틀렸다
```

대마도는 남한 0%라는 이유만으로 "북한전용"에 들어가 다운로드 목록에 올랐다.
**북한 경계와의 교차를 확인하지 않았다.** 세 갈래로 나눠야 한다.

```python
if 남한 > 0:        남한
elif 북한 > 0:      북한          # 한반도 − 남한
else:               제3국 → 제외   # ← 이 칸이 없었다
```

### ②. 배치는 제외 이력을 모른다

`batch_grd_rtc_frost.py`는 **zip이 있으면 처리한다.** 어떤 씬이 왜 제외됐는지
알 방법이 없다. 제외를 "파일 삭제"로만 표현했기 때문에, 파일이 돌아오면
제외도 사라진다.

## 4. 판정값이 서로 다르다 — 어느 것을 믿나

같은 씬인데 셋이 다른 답을 낸다.

| 판정 방법 | `FAA4` | `B5F3` | 성격 |
| --- | ---: | ---: | --- |
| bbox | 통과 | 통과 | 과대 — 빈 삼각형을 육지로 셈 |
| STAC 공칭 geometry | 0% (①) | >0% | 카탈로그 값, 실제와 다를 수 있음 |
| **KML 실측 footprint** | **29.5%** | **0.00%** | ✅ **정본** |

**원본 zip의 `preview/map-overlay.kml`이 정본이다.** ①에서 `FAA4`를
제외했던 판정도 공칭 geometry 기반이라 재검토 대상이다(29.5%면 정당한
한반도 프레임이다).

## 5. 재발 방지

- [ ] **①** 받은 직후 KML footprint로 재판정하는 관문. 한반도 1% 미만이면
      `excluded_china_japan/`으로 자동 격리. 검색 단계에서 못 막으니 여기서 막는다.
- [ ] **②** 제외를 **파일 삭제가 아니라 목록**으로 표현. `data/excluded_scenes.csv`
      (씬ID·판정값·근거·일자)를 두고 배치·다운로드가 함께 참조하면 재유입돼도
      자동으로 걸러진다. rsync가 파일을 되돌려도 목록은 남는다.
- [ ] **③-2** 남/북/제3국 **세 갈래 분류**로 수정. "남한 아님 = 북한"을 버린다.
- [ ] **`8B48`류** 배치에 **산출물 유효화소 하한 검사**. 0%면 실패로 처리하고
      파일을 지워야 다음 실행이 건너뛰지 않는다.
- [ ] **`FAA4` 재검토** — 공칭 geometry로 제외됐으나 실측 29.5%다.

## 6. 교훈

1. **판정은 bbox로 하지 않는다.** 이건 이미 알던 것인데 세 번 다 다른
   자리에서 샜다. 아는 것과 관철하는 것은 다르다.
2. **"A가 아님"은 "B임"이 아니다.** 이분법으로 좁히면 제3의 경우가 조용히
   한쪽에 섞인다.
3. **제외는 상태가 아니라 기록이어야 한다.** 파일을 지워 표현한 제외는
   파일이 돌아오면 사라진다.
4. **빈 산출물은 성공으로 보인다.** 크기·유효화소를 안 보면 배치는 영원히
   건너뛴다.
5. **검색은 넓게, 판정은 엄격하게.** bbox를 넓힌 것은 옳았다. 넓힌 만큼
   **뒤에서 거르는 관문**을 같이 만들었어야 했다.
