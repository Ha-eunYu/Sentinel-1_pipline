# 한반도 시계열 비교의 baseline 설계 (2026-08-17)

## 0. 왜 새로 잡아야 하나

목표가 바뀌었다.

| | 이전 | 현재 |
| --- | --- | --- |
| 대상 | 남한 가뭄 **또는** 북한 홍수 | **한반도 전체** |
| 비교 | 25 ↔ 26년 7·8월 | 같음 → 이후 **22~24년 추가 시계열** |
| 입력 | VV · 자동 DEM | **VH · Frost · external DEM** |

기존 baseline(`downloads/water/baseline_*`)은 **2026년 7월 홍수 탐지용**이다.
pre-event(6/25~7/7) 관측을 합성해 "홍수 전 평상시 수체"를 만들고, 그와 비교해
신규 침수를 뽑는 구조였다. 이 설계는 지금 목표에 맞지 않는다.

**세 가지가 걸린다.**

1. **재료가 없다.** pre-event 날짜 중 6/25·6/26은 원본이 삭제됐고, 7/4·7/6·7/7은
   남한 0% 궤도라 VH를 만들지 않았다.
2. **임계값이 안 맞는다.** 기존 baseline은 고정 −16 dB인데 이건 **VV 기준**이다.
   VH는 약 6 dB 낮아 그대로 쓰면 물을 거의 못 잡는다.
3. **개념이 안 맞는다.** "사건 전 평상시"라는 단일 기준면은 **한 사건**을 볼 때
   쓰는 것이다. 여러 해를 견주는 시계열에서는 기준면 자체가 해마다 달라진다.

---

## 1. 제안 — baseline을 "기준 영상"이 아니라 "기준 조합"으로 정의한다

시계열 비교에서 필요한 것은 *하나의 기준 래스터*가 아니라
**무엇과 무엇을 견줄지의 규칙**이다. 다음 3층으로 잡는다.

### 층 1. 비교 단위 — (상대궤도 × 대권역)

같은 상대궤도끼리만 붙인다. 궤도가 다르면 입사각·촬영기하가 달라 dB 분포가
다르기 때문이다([RELATIVE_ORBITS_KR.md](../pipeline/RELATIVE_ORBITS_KR.md)).
대권역으로 나누는 이유는 한강처럼 한 궤도가 다 못 덮는 유역이 있어서다.

```text
비교 단위 = (상대궤도 r, 대권역 b)
   값(연도 y) = 수체면적( r, b, y )   ← 공통 관측영역 마스크 적용 후
```

### 층 2. 기준 연도 — 고정 기준이 아니라 **쌍 비교 + 다개년 중앙값**

두 가지를 병행한다.

**(a) 쌍 비교 (25 ↔ 26년)** — 지금 당장 가능한 것

| 상대궤도 | 2025 | 2026 | 비고 |
| ---: | --- | --- | --- |
| **134** | 07-18 (S1C) | 07-20 (S1C) | 위성 동일, 한반도 커버 최대 |
| **54** | 07-25 (S1C) | 07-15 (S1C) | 위성 동일 |
| 127 | 07-24 (S1A) | 07-14·26 (S1D) | 위성 다름 |
| 61 | 08-06·12 | 07-03·27, 08-08 | 25년 표본 얕음(ISSUES 참고) |

**(b) 다개년 중앙값 (22~26년 확보 후)** — 최종 형태

각 (상대궤도 × 대권역)마다 **연도별 값의 중앙값**을 기준선으로 삼고, 개별
연도를 그 대비 편차로 표기한다. 평균이 아니라 중앙값을 쓰는 이유는 홍수·태풍
직후 관측이 한 해를 통째로 끌어올리기 때문이다(26년 7/14 사례, ISSUES #9).

```text
기준선(r, b) = median{ 면적(r, b, 2022..2026) }
편차(r, b, y) = 면적(r, b, y) / 기준선(r, b) − 1
```

**5개년 연속으로 한반도를 덮는 궤도는 rel 54·127 둘뿐**이므로, 다개년 중앙값은
이 두 궤도에서만 성립한다. 나머지는 쌍 비교로 남는다.

### 층 3. 시기 정합 — "같은 달"이 아니라 "같은 위상"

7·8월은 장마·태풍이 섞인다. 날짜만 맞추면 강우 사건이 비교를 지배한다.
관측일을 **강우 사건 기준으로 태그**해 같은 위상끼리 비교한다.

| 태그 | 정의 | 용도 |
| --- | --- | --- |
| `dry` | 직전 5일 누적강우 적음 | **가뭄 비교의 기본** |
| `wet` | 직전 5일 강우 큼 / 사건 직후 | 젖은 토양 과대추정 위험(ISSUES #9) |
| `flood` | 홍수 사건 구간 | 홍수 분석용, 가뭄 비교에서 제외 |

강우 자료는 기상청·GPM 등 외부 자료가 필요하다. 당장 없으면 **임계값·분리도로
대리 판정**할 수 있다 — 젖은 토양이 섞인 관측은 임계값이 2~3 dB 높고 분리도 η가
낮게 나온다(26년 7/14가 정확히 그랬다).

## 2. VH 임계값을 새로 정해야 한다

기존 고정 −16 dB는 VV 기준이다. VH는 물/육지 대비가 다르고 절대값도 낮다
(실측 오프셋 약 6 dB). 선택지는 셋이다.

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| **A. 궤도별 타일기반 Otsu** (현행 VV 방식 유지) | 궤도·시기별 조건을 스스로 흡수. 임계값을 고정할 필요 없음 | 이봉 타일이 부족하면 fallback으로 물러남 |
| B. VH 고정 임계값 재보정 | 단순·재현 쉬움 | 시기·궤도가 바뀌면 다시 틀어짐 |
| C. VV/VH 비율 또는 편파 조합 | 물 판별력 향상 여지 | VV도 만들어야 함(현재 삭제) |

**권장은 A**다. 이미 검증된 경로이고(타일기반 Otsu), 연도·궤도가 늘어날수록
고정 임계값은 유지가 어렵다.

### VH fallback 임계값 — 실측으로 정했다 (2026-08-17)

`s1/tools/audit/vh_threshold_probe.py`로 VH 산출물 8씬의 히스토그램에서 물·육지
봉우리와 골짜기를 쟀다.

| 항목 | VV (기존) | **VH (실측)** |
| --- | ---: | ---: |
| 육지 봉우리 | 약 −8 dB | **−13.2 ~ −14.0 dB** |
| 물 봉우리 | 약 −22 dB | **−30 dB 부근** |
| 물/육지 골짜기 | 약 −18 dB | **중앙값 −22.15 dB** (범위 −23.6 ~ −19.3) |
| fallback | −16 dB (골짜기+2) | **−20 dB** (골짜기+2) |

**판정 원칙**: 물이 아닌 것을 물이라 해도 되지만, **물인 것을 물이 아니라고 하면
안 된다.** `dB < 임계값`을 물로 보므로 임계값을 키울수록 물 판정이 넓어진다.
그래서 골짜기 그대로가 아니라 **골짜기보다 높은 쪽**으로 민다.

- **−20 dB 권장** — VV에서 골짜기(−18)에 +2 dB를 얹어 −16을 쓴 것과 같은 여유.
- **−19 dB는 더 안전한 선택** — 표본 중 가장 느슨한 골짜기(−19.25)까지 덮으므로
  어떤 씬에서도 물을 놓치지 않는다. 대신 젖은 토양·그림자가 더 섞인다.
- 골짜기가 −19.25로 얕게 나온 3개 씬은 이봉이 약한 경우다(물 봉우리와 골짜기가
  같은 위치로 잡혔다). **이런 관측은 fallback이 걸리면 비교에서 빼는 편이 낫다.**

```bash
conda run -n s1_snappy python -m s1.tools.audit.vh_threshold_probe --margin 1.0
```

## 4. 권장 순서

1. **rel 134·54 쌍으로 파이프라인을 먼저 완성한다** — 공통 관측영역 마스크 →
   대권역 클립 → 면적 산정. 표본이 작아도 **절차를 확정**하는 게 먼저다.
2. 그 절차로 **8월 원본을 채워 rel 127·61까지 확장**한다.
3. **22~24년을 받아 다개년 중앙값으로 전환**한다. 이때 rel 54·127만 쓴다.
4. 강우 태그를 붙여 `dry` 구간만 추려 가뭄 지표를 만든다.

> **주의**: 1~2단계 결과는 "표본 2개년의 쌍 비교"다. **평년 대비 가뭄**이라고
> 말하려면 3단계가 필요하다. 보고 문구에서 이 구분을 흐리지 말 것.
