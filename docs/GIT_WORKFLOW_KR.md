# Git 작업 방침 — 브랜치와 PR 을 언제 쓰나 (2026-08-21)

혼자 쓰는 저장소다. **절차를 위한 절차는 두지 않는다.** 대신 **나중에 "왜 이렇게
했지"를 찾게 될 변경**에만 무게를 싣는다.

관련: [PREPROCESSING_SPEC_KR.md](pipeline/PREPROCESSING_SPEC_KR.md)(전처리 규격 정본) ·
[BBOX_RANGES_KR.md](pipeline/BBOX_RANGES_KR.md) · [ISSUES_KR.md](worklog/ISSUES_KR.md)

## 1. 기본은 main 에서 바로 작업한다

혼자 쓰고 이력이 선형이라 **브랜치가 주는 이득이 거의 없다.** 브랜치를 파면
머지 시점을 관리해야 하는 일만 는다.

```bash
git add -A && git commit -F msg.txt   # 한글 메시지는 파일로 (ISSUES #11)
git push
```

## 2. 브랜치를 판다면 — 며칠 안에 머지한다

**되돌릴 수 있어야 하는 실험**에는 브랜치가 맞다. 다만 **수명을 짧게 잡는다.**

> ### ⚠ 머지 신호: 브랜치 이름이 내용을 설명하지 못하게 되면 그때가 머지할 때다
>
> 실제로 한 번 놓쳤다. `vh-rtc-cop30-lsmask` 는 2026-08-03 에
> **"VH RTC + COP30 + LS 마스크"** 실험용으로 팠는데, 머지 시점을 놓치고
> **17일간 57개 커밋**이 그 위에 쌓였다. 8월 한반도 전처리·대시보드·촬영계획
> 도구·이슈 등록 도구·범위값 문서까지 전부 들어갔다.
>
> 그 사이 `main` 은 7/30 에서 멈춰 있었다. **실험용 가지가 본선이 되고 본선이
> 방치되는 것** — 이게 "git 이 꼬였다"고 느껴지는 상태의 정체였다.
> 충돌은 없었다. 분기도 없었다. **머지를 안 했을 뿐이다.**
>
> 2026-08-21 에 `--ff-only` 로 정리했다(병합커밋 없음, 커밋 57개 그대로 보존).

머지는 선형이면 fast-forward 로 한다. `--ff-only` 는 안전장치다 — 분기가 있으면
병합커밋을 만드는 대신 **거부**한다.

```bash
git checkout main
git merge --ff-only <브랜치>
git push
git branch -d <브랜치>                    # 머지 끝난 가지는 지운다
git push origin --delete <브랜치>
```

## 3. PR 을 여는 기준 — "이미 만든 산출물의 의미가 바뀌는가"

이 하나로 판단한다.

> **기존 산출물을 무효로 만들거나 다시 만들게 하는 변경이면 PR 을 연다.**

혼자여도 값이 있는 이유는 **리뷰가 아니라 기록**이다. 몇 달 뒤 "왜 VV 를 버렸지",
"왜 Refined Lee 를 안 쓰지"를 반드시 다시 묻게 된다. 그때 근거·실측·대안을 한
화면에서 볼 수 있는 자리가 PR 이다.

### PR 을 여는 변경 (실제 사례)

| 변경 | 왜 PR 감인가 | 근거 문서 |
| --- | --- | --- |
| **편파를 VH 로 전면 전환** | VV 산출물 전량이 못 쓰게 된다. VV 와 **약 6 dB 오프셋**이라 섞을 수도 없다 | [사양서 2절](pipeline/PREPROCESSING_SPEC_KR.md) |
| **Speckle 필터 Refined Lee → Frost** | 이전 산출물의 수체 면적이 전부 달라진다. Refined Lee 는 **가는 선을 절반, 경계를 80% 날린다** | [FILTER_COMPARISON_KR.md](pipeline/FILTER_COMPARISON_KR.md) · 사양서 3절 |
| **판정 경계 shp 교체** | 커버율·선별 결과가 소급해서 바뀐다. `South_Korea.geojson` 은 제주·부산·강릉을 뺐다 | [ISSUES #7](worklog/ISSUES_KR.md) · [BBOX_RANGES_KR.md](pipeline/BBOX_RANGES_KR.md) |
| **external DEM 범위 변경** | DEM 밖은 **조용히 결측**이 된다. 범위가 다른 산출물을 섞으면 면적 비교가 깨진다 | [ISSUES #13 · #17](worklog/ISSUES_KR.md) · 사양서 1절 |
| **대량 재처리** (수십~수백 씬) | 수십 시간이 들고 되돌리려면 또 그만큼 든다 | 사양서 2-1절(시간 실측) |
| **산출물 규약·스키마 변경** | 파일명·밴드 구성·좌표계가 바뀌면 하류 도구가 전부 깨진다 | 사양서 6절 |

### 지름길 — 사양서 7절을 건드리면 PR

[사양서 7절 "바뀌면 안 되는 것"](pipeline/PREPROCESSING_SPEC_KR.md) 다섯 항목이
사실상 PR 목록이다.

```text
1. 편파 VH          2. 필터 Frost        3. DEM korea_peninsula_cop30.tif
4. EGM 보정 끄기    5. 10 m · EPSG:4326 · dB
```

**이 중 하나라도 바꾸려 하면 PR 을 연다.** 바꾸지 않는다면 PR 은 필요 없다.

### PR 을 열지 않는 변경

문서 갱신, 버그 수정, 도구 추가, 이슈 등록, UI 손보기 — **산출물의 의미를 바꾸지
않는 것.** 지금까지 한 작업 대부분이 여기 해당한다.

## 4. PR 을 열 때

```bash
# 한글은 인자로 넘기지 않는다 — 파일로 (ISSUES #11)
gh pr create --base main --head <브랜치> --title "<ASCII 또는 짧은 제목>" --body-file pr.md
```

본문에 **반드시** 넣을 것:

1. **무엇이 무효가 되나** — 재처리 대상 씬 수, 예상 시간(씬당 100분 / 2병렬 =
   시간당 1.2씬), 디스크 증가량
2. **근거 실측** — 표로. "느낌"이 아니라 숫자
3. **검토한 대안과 버린 이유**
4. **되돌리는 법**
5. 관련 이슈 — 닫힐 이슈는 `Closes #17`

머지는 **`--merge` 또는 fast-forward**. `--squash` 는 커밋 메시지를 뭉개고,
`--rebase` 는 이미 push 된 브랜치의 해시를 새로 써서 이력이 어긋난다.
이 저장소는 커밋 메시지에 근거를 적어왔으므로 **뭉개면 손해다.**
