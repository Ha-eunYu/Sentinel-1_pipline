## 1. 🔴 footprint 필터 적용 시점과 과거 산출물 재검증

이로 인해 다음 수치가 아티팩트로 확인됐습니다.

| 7/17 남한 침수 | 97.38 km² | 물 픽셀이 전부 동해~일본 방향 먼바다 |

## 2. 🔴 RTC 산출물이 실제 footprint를 잃어버림

### 이 프로젝트에서 관찰한 증거

`rtc_grd/*_rtc_db.tif`의 geotransform을 열어 보면 **회전항이 0**입니다.

```text
S1A_IW_GRDH_1SDV_20260625T093113_..._0999_COG_rtc_db.tif
  GeoTransform: (125.59313, 8.98315e-05, 0.0, 35.91481, 0.0, -8.98315e-05)
                                         ^^^                ^^^  회전항 = 0
  → 추출 코너: (125.5931,35.9148) (128.6920,35.9148)
               (128.6920,33.7707) (125.5931,33.7707)
  → lon 2종·lat 2종 = 축정렬 직사각형(bbox)
```

같은 씬의 원본 `manifest.safe`는 4점이 모두 다릅니다.

```text
  (125.5935,35.5184) (128.3397,35.9148) (128.6921,34.1694) (126.0038,33.7706)
  → lon 4종·lat 4종 = 기울어진 평행사변형(실제 footprint)
```

**즉 RTC 처리를 거치면 실제 촬영 형상 정보가 소실되고 bbox만 남습니다.**

### 실제 피해 사례 (보고용 폴더에서 발생)

RTC 산출물의 좌표로 촬영지역을 판정했다가 다음 오판이 났습니다.

| 씬 | RTC bbox 판정 | 실제 footprint |
|----|---------------|----------------|
| `..._3167_COG` | 제주 (서귀포시·제주시) | 북쪽 변이 마라도보다 **약 2.8 km 남쪽** 통과 |
| `..._5C3C_COG` | 강원 고성군 | 동해상 프레임, bbox 모서리만 고성군을 스침 |

### 확인할 것

- [ ] RTC 산출 시 원본 `manifest.safe`의 footprint를 **사이드카로 함께 저장**하는지
      (`*_footprint.geojson` 등)
- [ ] 저장하지 않는다면, 유효 픽셀 마스크(NoData 경계)에서 실제 외곽선을 추출해
      보관할 수 있는지
- [ ] 하류 분석에서 촬영범위를 판정할 때 **RTC 래스터 범위가 아니라 원본
      footprint**를 참조하는지

### 조치 제안

RTC 출력 폴더에 씬별 footprint GeoJSON을 함께 떨어뜨리면, 하류에서 bbox를 쓸
이유가 없어집니다. 비용은 파일당 수 KB입니다.

## 3. 🔴 수체 임계값 결정 로직·근거

### 이 프로젝트에서 관찰한 증거

QGIS 산출물 파일명에 적용 임계값이 남아 있는데, **씬마다 다릅니다.**

| 임계값 | 적용 씬 |
|--------|---------|
| −13 dB | `303C`, `392D` |
| −11 dB | `8EF1` |
| −10 dB | `59A8`, `DD29` |

**3 dB는 후방산란 강도 2배 차이**입니다. 같은 이벤트·같은 센서인데 씬별로
수체 경계를 다르게 그은 셈이라, 지역 간·날짜 간 면적 비교의 신뢰도가 떨어집니다.

씬별 조정 자체는 물리적으로 정당할 수 있습니다(입사각·풍속·표면거칠기가 다름).
문제는 **왜 그 값을 골랐는지 기록이 없다**는 점입니다.

### 확인할 것

- [ ] 임계값이 **코드에 하드코딩**돼 있는지, 설정 파일인지, 수동 입력인지
- [ ] 자동 임계값(Otsu, KI, 이봉성 검정 등)을 쓰는 경로가 있는지
- [ ] 씬별로 다른 값을 쓴 근거(히스토그램 등)가 로그로 남는지
- [ ] 임계값을 바꿨을 때 면적이 얼마나 변하는지 **민감도**를 산출한 적이 있는지

### 조치 제안

- 자동 임계값 도입, 또는 최소한 씬별 히스토그램·선택 근거를 로그로 저장
- 산출물 속성 또는 사이드카에 **적용 임계값을 기록**
- 보고서에 `면적 ± (임계값 ±1 dB 변동폭)`을 병기하면 수치 방어력이 크게 올라감

## 4. 🔴 전/후 차분(상시 수체 제거) 단계 존재 여부

### 이 프로젝트에서 관찰한 증거

보고용 폴더에 남은 중간 산출물 `Intersection.geojson`(이천군, `id=10`)을
홍수 전 baseline(6/26 수체)과 교차해 봤습니다.

```text
Intersection.geojson       : 2,986개, 12.163 km²
6/26 baseline 수체(이천군) :   831개,  5.575 km²

Intersection ∩ baseline    : 4.4443 km²  → Intersection의 36.54%
```

**최종 전 단계 산출물에 상시 수체가 면적 기준 36.5% 포함돼 있습니다.**

이것이 ① 차분 **전** 단계라서 당연한 것인지, ② 차분을 **누락**한 것인지
보고용 폴더의 파일만으로는 판단할 수 없었습니다. ②라면 상시 하천·저수지·논이
침수로 계상됩니다.

### 확인할 것

- [ ] 파이프라인에 **전/후 차분 단계가 있는지** (after 수체 − before 수체)
- [ ] 차분을 쓴다면 before 영상 선정 기준은 무엇인지 (최근접? 다중 평균?)
- [ ] 차분 대신 **상시 수체 마스크**(JRC Global Surface Water 등)를 쓰는 옵션이
      있는지 — before 영상이 없거나 품질이 나쁠 때 대안이 됨
- [ ] 보고서에 실린 수치가 차분 **후** 값인지 확인

### 참고 수치 (대조용)

보고서의 이천군 침수 면적이 **12 km²대**면 상시 수체 포함, **7~8 km²대**면
차분 반영으로 볼 수 있습니다.

## 5. 🔴 전/후 공통 촬영영역 교집합 처리

### 배경

홍수 **전** 영상이 덮지 않은 구역을 "새로 생긴 물"로 오인하면 침수 면적이
부풀려집니다. 이 함정은 **2024년·2026년 두 번** 발생했습니다
(`FLOOD_NORTH_KOREA_KR.md`에 최초 규명 기록이 있다고 문서에 언급됨).

### 이 프로젝트에서 관찰한 좋은 실무

보고용 폴더의 `flood_nk_20260725_fin.gpkg`는 **행정구역 ∩ 위성 촬영범위**로
잘린 폴리곤을 관리하고 있었습니다. 군별 관측률을 추적한 셈입니다.

| 군 | 관측 면적 | 군 전체 | 관측률 |
|----|-----------|---------|--------|
| 이천군 | 584 km² | 629 km² | 93% |
| 황주군 | 272 km² | 385 km² | 71% |
| 신평군 | 482 km² | 1,185 km² | 41% |
| 천마군 | 98 km² | 551 km² | 18% |
| 세포군 | 182 km² | 1,067 km² | **17%** |

이 관리는 **수작업으로** 이뤄진 것으로 보입니다.

### 확인할 것

- [ ] 파이프라인이 **before/after 영상의 공통 촬영영역**을 계산해 그 안에서만
      차분하는지
- [ ] 관측률(대상 지역 중 몇 %를 실제로 봤는가)을 산출물 속성으로 내보내는지

### 조치 제안

차분 전에 `after_footprint ∩ before_footprint`를 구해 마스크로 쓰고, 지역별
관측률을 산출물 속성에 넣으면 보고서에서 한계를 명시하기 쉬워집니다.

## 6. 🟡 shadow / layover 마스크 미적용

### 이 프로젝트에서 관찰한 증거

보고용 폴더의 SNAP 그래프(`s1_grd_to_rtc_db.xml`) 처리 순서입니다.

```text
Read → Apply-Orbit-File → ThermalNoiseRemoval → Calibration
     → Speckle-Filter → Terrain-Flattening → Terrain-Correction
     → LinearToFromdB → Write
```

Terrain-Correction까지 하지만 **layover/shadow 마스크를 저장하거나 적용한
흔적이 없습니다.** 산지 음영은 저후방산란이라 **물로 오탐**됩니다. 북한 분석
대상지(신평군·세포군·천마군 등)가 산지라 영향이 클 수 있습니다.

### 확인할 것

- [ ] `Terrain-Correction`의 `saveLayoverShadowMask` 옵션을 켜는지
- [ ] 켠다면 수체 판정에서 그 마스크를 **실제로 제외**하는지
- [ ] `Speckle-Filter`의 필터 종류·윈도우 크기가 무엇인지 (문서화 필요)
- [ ] Terrain-Flattening/Correction에 쓰는 **DEM 종류와 해상도**

## 7. 🟡 스페클 잔여·최소 면적(MMU) 필터

### 이 프로젝트에서 관찰한 증거

폴리곤화 결과의 피처 수가 비정상적으로 많습니다.

| 산출물 | 피처 수 | 총면적 | 평균 폴리곤 크기 |
|--------|---------|--------|------------------|
| `polgonize_clip_DD29_-10` | **198,458** | 2,252 km² | 11,350 m² |
| `polgonize_clip_8EF1_-11` | **80,538** | 248 km² | 3,080 m² |
| `polgonize_clip_59A8_-10` | 25,154 | 443 km² | 17,620 m² |
| `polgonize_clip_303C_-13` | 10,728 | 41 km² | 3,830 m² |

10만 개 단위의 폴리곤은 **스페클 잔여로 생긴 미세 오탐**이 대부분일 가능성이
높습니다. 개별 폴리곤 평균 3,000 m²는 10 m 해상도 기준 30픽셀 수준입니다.

### 확인할 것

- [ ] 수체 마스크에 **최소 면적(MMU) 필터**를 적용하는지 (예: 0.01 km² 미만 제거)
- [ ] 형태학적 연산(opening/closing)으로 노이즈를 정리하는지
- [ ] Speckle-Filter가 충분히 동작하는지 (필터/윈도우 재검토)

## 8. 🟡 정확도 검증 절차 부재

### 확인할 것

- [ ] 수체 판정 결과를 **광학 영상**(Sentinel-2 등)과 대조한 적이 있는지
- [ ] 오탐률·누락률 등 정확도 지표를 산출한 적이 있는지
- [ ] 보고서 수치에 **오차 범위**를 제시할 근거가 있는지

### 참고: SAR 수체 판독의 알려진 오차원

| 오차원 | 영향 | 면적 편향 |
|--------|------|-----------|
| 지형 그림자(shadow) | 산지 음영이 저후방산란 → 물로 오탐 | 과대 |
| 레이오버(layover) | 급사면 기하 왜곡 | 불확실 |
| 풍파(wind roughening) | 수면이 거칠어져 밝아짐 → 물 누락 | 과소 |
| 도심 침수 | 건물 이중반사에 가려 탐지 불가 | 과소 |
| 스페클 잔여 | 미세 오탐 폴리곤 다수 | 과대 |

**보고 시 최소한 이 표의 존재를 각주로 남기는 것만으로도** 수치의 해석 여지를
정확히 전달할 수 있습니다.

## 리뷰 시 활용 가능한 도구

이 폴더에 있는 것들입니다. 상위 프로젝트에도 동일본이 있을 수 있습니다.

| 도구 | 용도 |
|------|------|
| `footprint/footprint_aoi.py` | footprint ↔ 경계 교차 판정, bbox 오판 수치화 (`compare_bbox_vs_footprint`) |
| `footprint/verify_scene_footprint.py` | 처리된 래스터의 물 픽셀이 정말 경계 안인지 사후 검증 |
| `footprint/export_frames_geojson.py` | 프레임 footprint를 QGIS용 GeoJSON으로 내보내기 |
| `ref/*.gpkg` | 남한 읍면동 / 북한·일본·중국 국경 폴리곤 |
| `scripts/build_inventory.py` | 제품 메타데이터에서 촬영지역·시간 자동 추출 |

### bbox 오판 수치화 예시

```python
from footprint import compare_bbox_vs_footprint
print(compare_bbox_vs_footprint(item.bbox, item.geometry))
# {'bbox_intersects': True, 'footprint_intersects': False,
#  'bbox_false_positive': True, ...}
```
